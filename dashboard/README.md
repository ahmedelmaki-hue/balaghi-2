# لوحة موظف بلاغي

لوحة ويب عربية لإدارة البلاغات، متصلة بخادم المشروع وSupabase. يدخل الموظف الإداري والعامل الميداني باسم مستخدم وكلمة مرور؛ يتحقق الخادم من صلاحية كل دور، ولا تُحفظ كلمة المرور في قاعدة بيانات التطبيق.

## التشغيل المحلي في VS Code

شغّل Supabase المحلي والخادم أولًا وفق [تعليمات الخادم](../backend/README.md)، ثم افتح طرفية ثانية:

```powershell
cd dashboard
npm ci
npm run dev
```

افتح `http://127.0.0.1:5173` في المتصفح. أثناء التطوير يوجّه Vite طلبات `/api` إلى الخادم على `http://127.0.0.1:5000`؛ إن كان الخادم متوقفًا ستظهر رسالة اتصال بدل البيانات. حساب الموظف يُنشأ إداريًا حسب قسم **Create a staff account** في تعليمات الخادم. لا تسجل بيانات دخوله في ملفات المشروع.

لاختبار صفحة العامل الميداني على هاتف Android موصول عبر USB، أبقِ خادم API والداشبورد شغّالين، ثم نفّذ من PowerShell:

```powershell
& 'C:\Users\Asus\AppData\Local\Android\Sdk\platform-tools\adb.exe' reverse tcp:5173 tcp:5173
```

افتح `http://127.0.0.1:5173` في متصفح الهاتف وسجّل بحساب العامل الميداني. توجيه هذا المنفذ منفصل عن منفذ تطبيق المواطن `5000`، وقد يلزم إعادته بعد فصل USB.

### صفحة العامل على هاتف عبر Wi‑Fi (HTTPS)

المتصفح لا يفتح الكاميرا إلا على HTTPS أو `localhost`، فصفحة العامل المفتوحة بعنوان `http://192.168…` لا تستطيع التقاط صورة الإنجاز. لتجربتها عبر Wi‑Fi شغّل اللوحة بدل `npm run dev` بـ:

```powershell
npm run dev:https
```

ثم افتح على الهاتف `https://<IPv4-اللابتوب>:5173` (العنوان الذي تطبعه الطرفية تحت Network). تظهر مرة واحدة رسالة أن الشهادة غير موثوقة لأنها موقّعة ذاتيًا؛ اختر «متقدم» ثم «المتابعة». هذا مقبول للتطوير المحلي فقط؛ النشر الفعلي يحتاج شهادة حقيقية. طلبات `/api` تمر كما هي إلى الخادم المحلي.

## سير عمل البلاغ

يبقى بلاغ المواطن في «بانتظار المراجعة» ولا يظهر على الخريطة العامة. يفتح الموظف تفاصيله ليتحقق من الصورة والوصف والموقع، ويصحح التصنيف عند الحاجة قبل الاعتماد. عند الاعتماد يظهر البلاغ بحالة «جديد» ويُسنده النظام تلقائيًا إلى جهة العمل المختصة حسب التصنيف؛ يستلمه أحد عمالها بحسابه، ثم يؤكد بدء العمل فعليًا فتتغير حالته إلى «قيد المعالجة». عند إنجاز الإصلاح يلتقط العامل صورة جديدة من كاميرا صفحة العمل ويرسل طلب تأكيد الحل مع وصف اختياري. يحاول المتصفح تسجيل موقع الجهاز ودقته وقت التصوير؛ إن تعذر ذلك يظهر الأمر للموظف ولا يمنع الإرسال. يظهر الطلب في قسم «بانتظار تأكيد الحل» مع عدّاد في القائمة وتنبيه في النظرة العامة. يرى الموظف صورتي قبل وبعد الإصلاح وموقع الجهاز إن توفر، ثم يؤكد الحل فتتغير الحالة إلى «تم الحل»، أو يعيد البلاغ للعمل مع سبب يظهر للعامل. تبقى الحالة «قيد المعالجة» حتى التأكيد، وتُحفظ الصور والقرارات في سجل المراجعة.

تحتاج كاميرا المتصفح إلى إذن المستخدم وسياق آمن مثل `localhost` عبر توجيه USB أو HTTPS. لا توفر صفحة العامل اختيار صورة من المعرض، لكن الصورة والموقع يساعدان في المراجعة ولا يثبتان صحة الإصلاح وحدهما.

تضم اللوحة نظرة عامة، قائمة مراجعة، جدولًا مفلترًا بالصفحات، خريطة للبلاغات، إحصاءات، وتفاصيل البلاغ مع الصورة الكاملة وسجل المراحل. يرى عمال الجهة المختصة البلاغ المعتمد غير المستلم، ويستلمه أحدهم بحسابه ثم يؤكد بدء العمل من صفحة مناسبة للهاتف. لا يتغير البلاغ إلى «قيد المعالجة» إلا عند تأكيد بدء العمل. تفاصيل مقدم البلاغ تظهر للموظف الإداري فقط. الخريطة تحتاج اتصالًا بالإنترنت لتحميل بلاطات OpenStreetMap.

عند الشك في بلاغ قبل نشره، يختار الموظف «طلب تحقق ميداني» ويكتب سبب الطلب. يظهر في قسم مستقل لدى جهة العمل المختصة؛ يستلمه عامل من الجهة، يفحص الموقع، ويعيد النتيجة وملاحظة للموظف دون صورة إضافية. يظل البلاغ مخفيًا عن الخريطة العامة وتبقى حالته لدى المواطن «بانتظار المراجعة». يحدّث الموظف تفاصيل البلاغ لقراءة الرد ثم يعتمد البلاغ أو يرفضه. إذا كانت النتيجة «الموقع غير صحيح» يصحح الإحداثيات قبل الاعتماد. يمكن إلغاء طلب عالق مع تسجيل سبب الإلغاء.

إذا وجد عامل جهة العمل مشكلة في بلاغ معتمد، يمكنه إرسال سبب وملاحظة من شاشة التفاصيل حتى قبل استلام البلاغ. تُغلق نافذة الملاحظة بعد نجاح الإرسال، ويختفي البلاغ مؤقتًا من قائمة عمل الجهة وخريطة المواطنين، ويظهر في «تحتاج مراجعة ميدانية» داخل لوحة الموظف. يراجع الموظف الملاحظة ثم يقرر متابعة البلاغ فيعود إلى قائمة العمل، أو تصحيح موقعه، أو رفضه مع سبب يظهر لصاحبه. تبقى الحالات العامة الثلاث كما هي.

## البناء

```powershell
cd dashboard
npm run build
```

سيُنشأ مجلد `dist`. عند نشر الواجهة على عنوان مختلف عن الخادم، اضبط `VITE_API_BASE_URL` بعنوان API قبل البناء، واضبط سياسة CORS على الخادم لعنوان الواجهة. لا تضع مفاتيح Supabase السرية أو كلمة مرور الموظف في متغيرات Vite؛ الواجهة تستخدم جلسة الموظف فقط.
