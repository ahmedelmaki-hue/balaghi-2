# تطبيق بلاغي للمواطن

مشروع Flutter مخصص لـAndroid. المنفذ حاليًا هو صفحات الترحيب الأربع الموضحة في [التصميم](../docs/onboarding.md): السحب من اليسار إلى اليمين أو زر «التالي» ينقل إلى الصفحة التالية، وسهم الرجوع الذي يشير إلى اليسار يعيد إلى السابقة. زر «تخطي» تحت «التالي»، وتظهر رسوم متحركة قصيرة لكل صفحة. يمكن تخطي الصفحات أو الضغط على «ابدأ الآن» في نهايتها. تظهر صفحات الترحيب عند أول تشغيل فقط. لمراجعة تصميمها عند كل تشغيل، غيّر `_showOnboardingEveryLaunch` مؤقتًا إلى `true` في `lib/main.dart`.

بعد الترحيب تظهر الخريطة الرئيسية الفعلية وتطلب موقع الجهاز لتعرض منطقته أولًا. عند رفض الإذن أو تعذر تحديد الموقع تبقى الخريطة على الموقع الافتراضي، ولا تعود تلقائيًا إلى موقع المواطن بعد أن يحركها؛ زر الموقع يتيح العودة إليه. تشمل الخريطة فلاتر التصنيفات الثلاثة، علامات ملوّنة حسب الحالة، معاينة بلاغ قابلة للإغلاق، صفحة تفاصيل عامة، تحديثًا، وتكبيرًا وتصغيرًا. تعرض صفحة التفاصيل بيانات البلاغ الفعلية ورقمه أسفل العنوان، وتتيح مشاركته عبر قائمة المشاركة في الهاتف؛ سهم الرجوع يعيد إلى الخريطة. تستخدم الخريطة نمط Bright الملوّن من OpenFreeMap المبني على بيانات OpenStreetMap، ويحتاج عرضها إلى الإنترنت.

تفتح أزرار «إبلاغ» و«بلاغاتي» و«حسابي» شاشات دخول المواطن: ترحيب، رقم هاتف ليبي، رمز OTP، ثم الاسم واللقب عند أول دخول. يستخدم التطبيق الدخول الحقيقي افتراضيًا في كل البناءات. لتجربة تصميم الدخول دون خادم، شغّله صراحةً بـ`--dart-define=BALAGHI_AUTH_PREVIEW=true --dart-define=BALAGHI_DEMO_MAP=true` فيعمل **وضع المعاينة**: استخدم أي رقم ليبي صحيح مثل `0912345678` والرمز الثابت `123456`. لا يرسل وضع المعاينة رسالة نصية ولا ينشئ حسابًا حقيقيًا؛ يحفظ بيانات المعاينة محليًا، فلا تتكرر خطوات الدخول عند الضغط على الأزرار لاحقًا على الجهاز نفسه. بعد إكمالها، يفتح زر «إبلاغ» مسار إنشاء البلاغ: التقاط صورة مباشرة بالكاميرا دون خيار المعرض، تصنيف ووصف، تحديد موقع، مراجعة، ثم شاشة تأكيد متحركة. عند تأكيد الموقع يظهر تنبيه للتحقق من موضعه ومراجعة الجهة المختصة للبلاغ. التصنيف يدوي حاليًا إلى أن يُربط تحليل الصور الحقيقي. وضع المعاينة يعرض تأكيدًا تجريبيًا فقط ولا يرسل البلاغ؛ عند تشغيل الدخول الحقيقي تُرسل الصورة والبيانات إلى الخادم وتُعرض نتيجة الإرسال. تعرض «بلاغاتي» قائمة البلاغات وحالاتها، وتعرض «حسابي» الاسم والهاتف وتعديل الاسم وتسجيل الخروج.

لتجربة الدخول الحقيقي على Supabase المحلي مجانًا، شغّل الخدمات والخادم وفق [خطوات الخادم](../backend/README.md)، ثم عطّل معاينة الدخول والخريطة وحدد عنوان الخادم:

```powershell
flutter run --dart-define=BALAGHI_AUTH_PREVIEW=false --dart-define=BALAGHI_DEMO_MAP=false --dart-define=BALAGHI_API_BASE_URL=http://10.0.2.2:5000/api
```

في هذا الوضع استخدم الرقم `0912345678` والرمز `123456`؛ الرمز مضبوط داخل Supabase المحلي، ولا تُرسل رسالة SMS. على هاتف حقيقي، استبدل `10.0.2.2` بعنوان IP المحلي للكمبيوتر، ووصل الهاتف والكمبيوتر بالشبكة نفسها. يحفظ التطبيق جلسة المواطن في التخزين الآمن للجهاز. نسخة Release تستخدم الدخول الحقيقي افتراضيًا، ويجب توجيهها إلى خادم HTTPS مناسب ومزوّد SMS فعلي قبل النشر.

في خطوة تحديد موقع البلاغ، يختار المواطن بين استخدام موقع هاتفه الحالي وتحديد موضع المشكلة يدويًا على الخريطة. لا يُطلب إذن GPS في هذه الخطوة إلا إذا اختار استخدام موقعه، ويجب مراجعة المؤشر وتأكيده قبل الانتقال للمراجعة.

يبدأ التطبيق في بناء Debug بوضع عرض تجريبي واضح يحتوي أربعة بلاغات افتراضية حتى يمكن معاينة التصميم قبل إعداد Supabase. لإظهار البلاغات الحقيقية من خادم Express بدلًا منها، شغّل الخادم ثم شغّل Flutter هكذا على محاكي Android:

```powershell
flutter run --dart-define=BALAGHI_AUTH_PREVIEW=false --dart-define=BALAGHI_DEMO_MAP=false --dart-define=BALAGHI_API_BASE_URL=http://10.0.2.2:5000/api
```

على هاتف حقيقي، استبدل `10.0.2.2` بعنوان IP المحلي لجهاز الكمبيوتر، ووصل الهاتف والكمبيوتر بالشبكة نفسها. قد تحتاج إلى السماح للخادم بالاستماع على الشبكة المحلية. الربط عبر HTTP مسموح في نسخة Android التجريبية فقط؛ استخدم HTTPS عند نشر الخادم.

عند إرسال بلاغ حقيقي يظهر لصاحبه في «بلاغاتي» بعبارة «بانتظار المراجعة»، ولا يظهر على الخريطة العامة حتى يعتمده الموظف. بناء Release يستخدم البيانات الحقيقية افتراضيًا؛ اضبط عنوان API المنشور قبل توزيعه.

للتشغيل الحقيقي من VS Code على محاكي Android: شغّل Supabase المحلي والخادم أولًا وفق [خطوات الخادم](../backend/README.md)، ثم افتح مجلد `Balaghi` في VS Code، واختر إعداد **«بلاغي - Supabase محلي (محاكي Android)»** من قائمة Run and Debug واضغط F5. ملفات `.vscode/launch.json` تضبط خيارات `--dart-define` المطلوبة تلقائيًا. يمكن أيضًا تشغيل المعاينة فقط من الطرفية بالأوامر:

```powershell
flutter pub get
flutter run
```

الفحص المحلي:

```powershell
flutter analyze
flutter test
```

## تجربة بلاغ حقيقي بهاتف Android عبر USB

فعّل **USB debugging** ووافق على نافذة السماح على الهاتف. شغّل Supabase المحلي والخادم، ثم اختر الهاتف من قائمة الأجهزة في VS Code. اختر إعداد **«بلاغي - Supabase محلي (هاتف Android عبر USB)»** واضغط F5. مهمة التشغيل تضبط `adb reverse tcp:5000 tcp:5000` تلقائيًا؛ وبذلك يصل التطبيق إلى API الحاسوب عبر `127.0.0.1:5000` دون الحاجة إلى عنوان IP أو اتصال الجهازين بشبكة Wi-Fi واحدة. إذا انفصل سلك USB، أعد تشغيل الإعداد بعد إعادة توصيل الهاتف. استخدم رقم الاختبار `0912345678` ورمز `123456`؛ لا تُرسل رسالة SMS في البيئة المحلية. بعد إرسال البلاغ يظهر في «بلاغاتي» بانتظار مراجعة الموظف.

إذا كان اتصال USB ينقطع أثناء التجربة، استخدم إعداد **«بلاغي - Supabase محلي (هاتف Android عبر Wi-Fi)»** بدلًا منه. هذا الإعداد يرسل الطلبات إلى عنوان الكمبيوتر المحلي `192.168.33.111`؛ الهاتف والكمبيوتر يجب أن يكونا على شبكة Wi-Fi نفسها، ويجب إبقاء الخادم وSupabase قيد التشغيل. يحتاج Flutter إلى USB لتثبيت نسخة التصحيح، لكن التطبيق يواصل الاتصال بالخادم عبر Wi-Fi إذا انقطع ربط `adb reverse`. عند تغيّر عنوان الكمبيوتر، حدّث `BALAGHI_API_BASE_URL` في `.vscode/launch.json` ثم شغّل التطبيق من جديد.
